## 二、技术方案与模型选型（约 3 分钟）

> **放 PPT：技术方案总览 + 模型/框架选型表**。

- 模型：`DeepSeek-R1-Distill-Qwen-1.5B`——基于 R1 推理数据蒸馏到 Qwen2.5 架构，算力要求低，适合**现场演示**；汇报中也说明可在更大算力下换成 8B 基座。
- 框架：**PEFT / LoRA** 参数高效微调，显存占用低、与 Transformers 兼容。
- 数据集：`medical_cot_zh.jsonl` 约 2 万条医学思维链问答（Question / Complex_CoT / Response）。

> 讲一句：**"为什么选 1.5B？"**——现场有 8GB 显卡，1.5B 能在几分钟内完成演示级微调，且能清楚看到"领域风格模仿"的差异。

> **强调 LoRA 配置**：`r=16, lora_alpha=32`，`target_modules` 覆盖全部注意力与 MLP 矩阵；训练参数 `2 epoch / lr=5e-5 / batch=1 / grad_accum=4 / eval_steps=50`。

## 八、Q&A 预备问答

| 可能的提问 | 参考回答 |
| --- | --- |
| 为什么选 LoRA 而非全参微调？ | 全参微调 1.5B 显存与耗时成本高；LoRA 只训练低秩矩阵，显存低、部署不依赖适配器，效果足以体现领域风格迁移。 |
| 为什么生成参数用 0.4/1.1/1024？ | 1.5B 长文本易漫谈重复；低温+长度惩罚+限长能稳定输出。默认 do_sample=1.0+超长 max_new_tokens 会失控（项目实测踩过坑）。 |
| 验证题为何选开放式问诊？ | 1.5B 基座对急诊急救类需精确判诊断的题易答错，教学演示聚焦"表达范式/结构规范"而非绝对诊断正确。 |
| 能直接用于临床吗？ | 不能。仅教学演示；临床需更大基座+严格医学验证+合规审查。 |
| 训练 1000 条够吗？ | 演示级够。生产级建议全量 2 万条及以上，并覆盖多维问法。 |
